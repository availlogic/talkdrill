# TalkDrill - Project Constraints

## 1. Technology Constraints (技术约束)

- **前端架构与框架选型**：
  - 采用现代 SPA 前端技术栈（React / Vue 3 + TypeScript + Tailwind CSS）。
  - 构建系统采用现代化打包工具，确保轻量级依赖树与高效 Tree-shaking。
- **本地存储引擎规范**：
  - 严禁使用受配额限制（5MB 至 10MB）的 `localStorage` 存储文本篇目或音频资产。
  - 所有文章数据、练习计数与音频文件必须存储在浏览器的 `IndexedDB` 中。
  - 必须采用 `Dexie.js` 进行结构化封装与类型安全查询定义。
  - 音频文件必须以原生二进制 `Blob` 格式存入 IndexedDB，杜绝 Base64 编码带来的内存膨胀。
- **音频处理引擎**：
  - 基于 HTML5 Audio 与 Web Audio API 构建播放引擎。
  - 必须实现变调不变速（Pitch-preserving）的播放速率调整（支持 0.5x, 0.75x, 1.0x, 1.25x, 1.5x）。
  - 支持高精度的 A-B 循环断点设置与微秒级定位。
- **离线与 PWA 规范**：
  - 必须配置标准 Web App Manifest 与 Service Worker 缓存策略。
  - 达成完全脱网（100% Offline）下篇目加载、音频播放与打卡记录的正常可用。
- **第三方接口协议规范**：
  - 翻译接口必须兼容 Anthropic API 规范（messages 协议格式）。
  - 在线 TTS 音频合成作为下代大版本升级规划特性，底层预置适配多供应商协议能力（兼容 OpenAI TTS、ElevenLabs、Minimaxi 或自定义端点）。

## 2. Platform Constraints (平台约束)

- **多端视口自适应断点**：
  - **桌面端 (Desktop: >= 1024px)**：
    - 采用双栏或三栏布局（篇目导航、主工作台、打卡看板）。
    - 优先支持物理键盘快捷键（Space 打卡 +1、Z 撤销 -1、R 重新播放、[ 与 ] 调节倍速）。
    - 常驻顶部或底部控制台，提供完整波形与操作指引。
  - **平板端 (Tablet: 768px 至 1023px)**：
    - 支持可折叠抽屉导航与自适应分栏（横屏双栏，竖屏上下堆叠）。
    - 触控交互优化，触控目标防误触边距保持 >= 16px。
    - 采用大图标卡片式浮动播放器。
  - **移动端 (Mobile: < 768px)**：
    - 单栏流式布局，抽屉式菜单让渡屏幕主体空间给朗读文本。
    - 文本行高设定为 1.8，字号自适应防止产生横向溢出滚动。
    - 底部常驻拇指操控热区，提供超大尺寸打卡胶囊按钮（高度 >= 56px），支持单手盲操。
    - 紧凑吸底迷你播放器（Mini Player），支持上滑展开全功能调节面板。
- **浏览器兼容性矩阵**：
  - 支持现代主流浏览器：Chrome 110+、Safari 16.4+、Firefox 115+、Edge 最新版。
  - 全面适配 iOS/iPadOS Safari 与 Android Chrome 的音频自动播放限制策略（必须经由用户手势激活 AudioContext）。

## 3. Infrastructure Constraints (基础设施约束)

- **静态站点托管**：
  - 客户端纯静态资源部署于 Cloudflare Pages。
- **边缘网关代理 (Cloudflare Workers)**：
  - 仅作为轻量级无状态反向代理，用于绕过浏览器直连外部模型与语音 API 时的 CORS 跨域限制，以及转发流式响应。
  - 必须遵循严格的无状态（Stateless）管道原则：用户 API Key 仅在请求头中单向透传至目标服务提供商。
  - 严禁在 Cloudflare Worker 端持久化、缓存或记录任何用户的私有语料、练习记录或 API 凭证。

## 4. Security Constraints (安全约束)

- **零数据上报与去中心化**：
  - 无中心化用户系统与云端业务数据库，杜绝任何形式的后端用户数据收集。
  - 所有语料、音频资产及打卡进度均留在用户本地环境。
- **凭据本地隔离 (BYOK)**：
  - 用户配置的第三方 API 凭证（如 Anthropic Key 等）仅保存在客户端本地存储中，不传输至任何第三方集中存储。
- **服务配置完全隔离**：
  - 翻译引擎与应用内其他配置保持相互独立，配置项禁止耦合；当前大版本默认关闭 TTS 设置面板。

## 5. Performance Constraints (性能约束)

- **首屏加载与体积预算**：
  - 生产构建产物经 Brotli 压缩后，核心资源总包体积必须 <= 300KB。
  - 首次内容绘制（FCP）必须控制在 <= 1.2s。
- **打卡交互响应**：
  - 打卡触发到 UI 正字渲染及数字更新的渲染延迟必须 <= 16ms（保持 60fps 帧率无掉帧）。
- **音频流加载响应**：
  - 从 IndexedDB 读取本地音频二进制 Blob 并装载至 Web Audio 播放上下文的加载延迟必须 <= 100ms。
- **文件体积限制**：
  - 纯文本文件导入单文件限制 <= 2MB。
  - 自定义本地音频上传（.mp3, .wav, .m4a）单文件限制 <= 50MB。

## 6. Deployment Constraints (部署约束)

- **自动化与部署通道**：
  - 前端部署目标为 Cloudflare Pages，边缘代理部署目标为 Cloudflare Workers。
- **Docker Compose 规则限制**：
  - 当涉及 Docker Compose 需求时，严禁在 IDE 内部直接自动执行 `docker compose` 命令。
  - 仅可向用户输出可执行的具体命令，由用户在宿主环境中手动执行并确认反馈。
- **Python 环境规范**：
  - 项目内涉及的任何辅助脚本必须使用 `uv` 进行环境与依赖管理（`uv run`, `uv add`, `uv remove`），严禁直接使用全局 pip 或 poetry。

## 7. Budget Constraints (预算与成本约束)

- **零服务器维护成本**：
  - 基础设施完全依赖 Cloudflare 免费配额架构，避免产生固定的月度服务器与数据库租赁费用。
- **终端调用成本控制**：
  - 提供本地示范音频上传导入选项，并支持音频的本地下载与离线导出。

## 8. Compliance Requirements (合规与标准约束)

- **打印排版标准 (@media print)**：
  - 严格实现打印媒体查询样式控制：自动隐藏导航、控制台与交互按钮。
  - 正文字号固定为 16pt 至 18pt，行高固定为宽松的 2.2，为纸质手写预留空间。
  - 打印页末必须自动生成 60 格或 100 格的空白方格打卡网格表（对应 300 遍或 500 遍练习）。
- **隐私保护与数据合规**：
  - 符合严格的隐私第一（Privacy-First）标准，不接入任何第三方追踪、统计分析 SDK 或广告脚本。
  - 本地数据应提供完备的清空与重置入口，保障用户对本地数据的完全控制权。

## 9. Coding Constraints (代码与工程规范)

- **排版规范**：
  - 严禁使用破折号 em dash，统一使用普通短横线 "-"。
- **开发方法论与 TDD 约束**：
  - 严格遵循测试驱动开发（TDD）流程：先编写失败测试用例，再编写最小可行代码使其通过，最后进行重构。
  - 所有新功能与修改必须具备对应的自动化测试覆盖。
- **代码复杂度与可维护性**：
  - 保持代码极简：单个函数行数严格控制在 30 行以内。
  - 单个函数的圈复杂度（Cyclomatic Complexity）严格控制在 10 以内。
- **静态分析与类型安全**：
  - 实行静态分析零告警政策：消除所有 Linter、Type-checker 告警。
  - 严禁使用规则抑制注释，严禁使用 `any` 等类型逃逸。
- **测试覆盖率与断言强度**：
  - 新增与修改代码必须达到 >= 90% 单元测试覆盖率。
  - 变异测试得分（Mutation Test Score）必须达到 >= 85%，确保测试断言具备足够的拦截能力。
- **模块化设计规范**：
  - 各功能模块需具备明确的输入定义与输出定义，保持最小外部耦合，并支持独立的单体测试或手动调用验证。

## 10. Known Assumptions (已知假设)

- 假设用户自行持有可用的 LLM 翻译服务接口权限或兼容代理端点。
- 假设宿主浏览器环境支持现代 Web 标准（IndexedDB, Web Audio API, Service Worker）且具备充足的本地磁盘空间配额。
- 假设移动端运行环境在用户产生首次点击/轻触后能够正常释放音频播放权限。

## 11. Explicit Non-Goals (明确非目标)

- **不构建集中式后端**：不设计多租户中心化用户认证、鉴权与云端数据存储系统。
- **不提供中心化媒体托管**：不对用户生成的音频或自定义语料进行云端集中备份或公开分发。
- **不开发语音识别评分 (ASR)**：不开发基于 AI 的发音准确率识别与机器打分体系，发音评价完全交给学习者的自主演练与听觉对比。
- **不开发复杂语法解析器**：不实现语法结构标注、词性分词与划词查词典系统。
